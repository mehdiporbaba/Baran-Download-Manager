# Mister Download Manager integration review

Snapshot: 2026-11-17. Reference: [Mister Download Manager](https://github.com/anefzaoui/misterdownloadmanager), source commit `714a1052f3c871021c054d6e96e1e800b16e80e1`. Read 46 documentation/source entry points; 367 extracted Rust/extension files match the pinned Git blob hashes. The [issue catalogue](reviews/mdm-issues-2026-11-17.json) indexes **588 non-PR reports, 38 open and 550 closed** returned by complete API pagination at collection time. Collection is not atomic; later GitHub counts may differ.

This is functional adaptation to Baran's native C#/WebView2/aria2 architecture. New code is original Baran code; MDM's Rust engine, pixel layout, icons, themes and artwork are not bundled. MDM declares GPL-3.0-or-later. Its own benchmark figures are not Baran measurements. The user explicitly requested Baran's existing blue identity and main-window layout.

The catalogue covers every collected report, but **does not claim all reports reproduced or all features implemented**. Categories are a search index derived from titles. Selected relevant reports were examined against source and tests; the table distinguishes new local code, existing behavior and gaps. The owner now authorizes final Windows publication with explicit limitations.

| Feature/workflow | Baran assessment and integration |
| --- | --- |
| Independent per-download progress | New native source: one window per task, shared core/WebView2 environment, status/limit/completion tabs, file-range map, connection rows and completion actions. Main app keeps its layout. Double-click/Enter reopens; closing/hiding keeps the transfer running. Visual acceptance is pending. |
| Progress lifecycle and placement | Automatic-open preference, per-file close-on-completion option, tray restore, screen-bounded placement and scoped RPC. Close never deletes data; Stop keeps the partial file. Bounds/policy fixtures pass; mixed-DPI GUI acceptance is not claimed. |
| Per-download/global bandwidth | New live HTTP task cap alongside the existing global cap. Changing/removing the cap wakes old waits; pause interrupts waiting. Per-file media/torrent caps and activity-aware throttling are not implemented. Existing torrent global upload/download caps remain. |
| Segmentation and resilience | Existing segmented range downloads, partial metadata, retries, strong-ETag/sample verification and pause/resume. New immutable segment snapshots avoid sharing worker-mutated dictionaries with windows. Adaptive host limits, work stealing, stalled-segment rescue and multi-mirror aggregation remain gaps. |
| Refreshed/expired URLs | Existing verified manual HTTP URL replacement is available in the new window. Automatic browser re-capture and automatic provider renewal are not delivered. |
| Download checksums | New optional expected SHA-256 for direct downloads, verification phase and actual digest. Mismatch keeps partial data and prevents final-file publication; correcting the digest can reuse saved bytes. Automatic trusted-host digest discovery and other algorithms remain gaps. |
| HTTP page versus requested file | New guard rejects an HTML login/challenge page returned for an explicitly non-HTML filename; explicit HTML/text downloads remain allowed. MIME detection alone cannot identify every disguised response. |
| Naming and collision safety | Native allocator already preserves existing files, numbers genuine collisions and updates the resulting name/path. Regression checks cover preserving the old file and avoiding a suffix for a fresh unchanged destination. Broader rename/move automation remains separate. |

App web proxy and authorized media cookie settings are separate. Inline PDF, blob, Google Drive confirmation flows, SPA/video overlays and additional browser variants need further work. No universal default-manager takeover. |

| Video/audio | Existing yt-dlp quality/audio/playlist support and absolute tool paths. New stderr progress handling, postprocessing state and missing-FFmpeg guard prevent silently accepting an unmerged separate-track selection. Real merging/live authenticated-site acceptance remains pending. |
| Galleries | Existing Instagram-specific extraction through gallery-dl and a separate review source. General gallery-site workflows, the full native HLS/DASH engine and broad overlay-based media discovery are not integrated. Protected content still needs authorized access. |
| Helper management | 2.1.0 installs/updates yt-dlp, official gallery-dl nightly, FFmpeg/ffprobe and Deno with required SHA-256, bounded fixed-name extraction and source/version stamps. Custom paths remain available. Health orchestration and multi-architecture packaging remain gaps; large helpers are separate downloads. |

Smart packages, Click'n'Load/DLC and safe multi-part archive extraction are not implemented. Archive traversal/password/overwrite limits need independent tests before extraction is added. |
| Debrid | 2.1.0 adds AllDebrid, Premiumize and TorBox HTTP-link contracts alongside Real-Debrid, with independent DPAPI vaults, durable pending IDs and multi-file review. Contract fixtures pass; live paid-account acceptance and full cloud-torrent/stream-selection workflows remain outside this scope. |

| Categories/save rules | Existing type categories and chosen destination. Editable categories and per-host/extension save-routing rules remain gaps. |
| VPN/DNS | Experimental IPv4-bound HTTP and DNS now also back media HTTP via an authenticated local proxy and native yt-dlp fetching; interface loss cancels media processes. Torrent binding, encrypted DNS and full system kill-switch behavior remain gaps. |
| Mobile/headless/CLI/MCP | Existing opt-in authenticated private-LAN mobile controls. Native headless product/server packaging, NAS/Docker, a full user CLI and MCP automation are not delivered; the test driver is not a supported public server. |

| Platform/update/security packaging | Native Windows x64 stays small and uses shared WebView2. Linux/macOS/ARM packaging, trusted Windows signing, a signed automatic updater and consistent internet-origin marking across all download kinds are not delivered. Do not import Rust graphics-driver workarounds as C# fixes without reproduction. |

## Relevant report checks

- [#1328](https://github.com/anefzaoui/misterdownloadmanager/issues/1328): Baran's local stalled-response test pauses within a bounded interval and preserves partial data. This tests the reported failure mode, not MDM itself.
- [#621](https://github.com/anefzaoui/misterdownloadmanager/issues/621): a task capped while active completes promptly after lifting its cap, without pause/resume; another task remains independent. Cancelable token budgeting avoids reserving future slots for canceled workers; segmented pause/resume is tested under both per-file and global caps.
- [#736](https://github.com/anefzaoui/misterdownloadmanager/issues/736): transfer positions are rendered from actual ranges; expected-hash verification and yt-dlp postprocessing have a distinct verifying state. Media progress on stderr reaches task events. No invented merge percentage.
- [#617](https://github.com/anefzaoui/misterdownloadmanager/issues/617): explicit separate-track/MP3 postprocessing refuses missing FFmpeg rather than labeling an unmerged selection complete. Fixture coverage does not prove every video's audio content.
- [#701](https://github.com/anefzaoui/misterdownloadmanager/issues/701): an HTML response cannot be accepted under the requested archive filename; explicit HTML remains downloadable.
- [#597](https://github.com/anefzaoui/misterdownloadmanager/issues/597) / [#1143](https://github.com/anefzaoui/misterdownloadmanager/issues/1143): old destination bytes stay intact and are not counted as a new completed transfer. A free destination keeps its original name.
- [#1311](https://github.com/anefzaoui/misterdownloadmanager/issues/1311), [#672](https://github.com/anefzaoui/misterdownloadmanager/issues/672), [#1268](https://github.com/anefzaoui/misterdownloadmanager/issues/1268): work-area placement and overflow/scrolling guards exist; native bounds tests cover negative/small displays. Browser visual checking was blocked by declined preview-origin permission, so actual layout/mixed-DPI acceptance is pending.
- [#694](https://github.com/anefzaoui/misterdownloadmanager/issues/694), [#818](https://github.com/anefzaoui/misterdownloadmanager/issues/818), [#440](https://github.com/anefzaoui/misterdownloadmanager/issues/440), [#1087](https://github.com/anefzaoui/misterdownloadmanager/issues/1087): integration invisibility, missing registration, handshake mismatch and inline-document coverage need separate real-browser checks. See [active P0 work](WORK-ITEMS.md); a durable URL alone is not visible-dialog acceptance.
- [#623](https://github.com/anefzaoui/misterdownloadmanager/issues/623) / [#917](https://github.com/anefzaoui/misterdownloadmanager/issues/917): unknown free space must not be treated as confirmed disk exhaustion. Baran does not gate downloads on the sidebar's disk-space display; network-volume/macOS acceptance is not claimed.
- Rust/egui/Direct3D rendering and macOS/Linux-specific reports remain runtime/platform findings, not confirmed identical Baran bugs. WebView2 has its own validation needs.

## Evidence and remaining acceptance

Native integration exercises pause under stalled reads/rate waits, checksum success/mismatch/recovery, independent live limits, collisions, HTML guard, media CLI phases, private local torrents and existing verified resume behavior. Connected fixtures test negative/small work areas and rejection of foreign-task/destructive/global commands from progress-window policy. Type checks and native/renderer compilation are required after changes. The visual QA harness `tests/progress-preview.cjs` uses an isolated real native engine and temporary profile; opening its browser origin was declined, so it was stopped without claiming visual success. No user browser/profile setting was changed for that test.

<li><strong>پلتفرم/به‌روزرسانی/بسته‌بندی امنیتی:</strong> نسخهٔ بومی ویندوز ۶۴ بیتی کوچک و متکی به WebView2 مشترک می‌ماند. بسته‌بندی Linux/macOS/ARM، امضای معتبر ویندوز، به‌روزرسان خودکار امضاشده و نشانه‌گذاری یکنواخت منشأ اینترنت برای همهٔ انواع دانلود ارائه نشده‌اند. راه‌حل درایور گرافیکی Rust بدون بازتولید به C# منتقل نشود.</li>
</ul>
