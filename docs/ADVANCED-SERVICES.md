# Advanced services in 2.1.0

The owner authorized a final **Windows x64** release with explicit limits; native Linux/macOS ports and full torrent VPN/proxy confinement are deferred. Chrome store publication is blocked on an owner developer account, not on creation of the submission ZIP. No payment, account creation or store submission was performed.

## Debrid

Settings → Connected services selects Real-Debrid, AllDebrid, Premiumize or TorBox. Tokens use independent Windows-user DPAPI vaults; the previous Real-Debrid vault remains compatible. Save/Test/Remove operate on the selected account. Only redacted account labels, configuration flags and pending job IDs reach the UI. Tokens never enter ordinary settings, Inbox results or mobile snapshots. Accounts and supported hosts must permit the request; generating links may consume quota.

Real-Debrid resolves HTTP links; AllDebrid supports direct and delayed links; Premiumize imports every returned direct-download file; TorBox creates a web-download job and checks it before requesting completed file links. Pending IDs survive restart. Checking does not submit a new source. Results remain tracked until the Inbox accepts them; a full Inbox can be cleared and checked again. Forget local tracking does not delete or cancel the remote cloud job. Streaming-quality selection and cloud-torrent management are not included. Requests are serialized for resolution, not blindly retried after a quota-consuming failure.

Official contracts reviewed on 2026-11-17: [AllDebrid](https://docs.alldebrid.com/), [Premiumize](https://www.premiumize.me/api?hl=en), [TorBox OpenAPI](https://api.torbox.app/openapi.json). TorBox requires its token in the request-link API query; that URL remains internal and is not saved as an Inbox link. Returned URLs containing the token are rejected. Live paid-account success has not been established by local contract fixtures.

## Media tools and routing

Settings → Tools offers per-tool installation/update. Downloads require the release API's SHA-256 digest and exact advertised byte length; extraction accepts fixed executable names only, rejects duplicates and bounds expanded sizes. A missing digest, mismatch or invalid executable stops installation. Existing managed binaries are replaced only after verification; the source/tag/digest is recorded alongside them. Custom paths still take priority. Downloads are optional, separate and much larger than the app installer.

yt-dlp uses its [official releases](https://github.com/yt-dlp/yt-dlp/releases). gallery-dl moved active development to Codeberg: its [maintainer README](https://github.com/mikf/gallery-dl#installation) identifies [gdl-org nightly builds](https://github.com/gdl-org/builds/releases); Baran uses that official nightly Windows executable, not an invented stable GitHub asset. [FFmpeg's download page](https://ffmpeg.org/download.html) links BtbN; the repository now resolves to [FFmpeg-Builds/FFmpeg-Builds](https://github.com/FFmpeg-Builds/FFmpeg-Builds/releases). Deno comes from [denoland/deno](https://github.com/denoland/deno/releases). Source migrations must be checked again when maintainers change distribution.

Selected-interface IPv4 HTTP binding routes DNS and outgoing sockets through the selected interface without default-route fallback. Supported media HTTP requests use the authenticated loopback proxy backed by those same sockets and DNS. yt-dlp is forced to its native downloader; FFmpeg is for local processing. Interface loss closes bound sockets and cancels the media process tree. This is transport routing, not OS sandboxing of arbitrary user-selected binaries or a system-wide kill switch. Torrent peers/DHT remain unconfined by the bundled aria2 engine and are therefore blocked when binding is enabled. Ordinary web proxies do not proxy torrent peers. Full IPv6 and torrent confinement require separate work.

## Distribution and evidence

Setup refuses to overwrite a running native app and asks the user to quit from Tray; it never kills transfers. After installation it registers Firefox's fixed ID and refreshes previous Chrome/Edge native-host origins while retaining valid IDs. Firefox's exact Mozilla-signed 1.0.2 XPI is bundled; the browser still owns Add and permission confirmation. The prepared unpacked Chromium folder is accessible from Settings. A real Chrome store URL/ID will be used only after owner registration and Google approval; ordinary Windows Chrome installation cannot be replaced by a self-signed CRX.

`tests/advanced.integration.mjs` checks local AllDebrid/Premiumize/TorBox contracts, durable jobs, secret redaction, multi-file mapping, authenticated media proxy use with a real bound source address, process cancellation on interface loss, digest verification and constrained archive extraction. Native/connected integration covers direct download integrity, Real-Debrid, wake tasks, mobile pairing and browser IPC. These are not live-account, real-browser/cold-start, visual or full security-audit claims. Firefox direct-link handoff was separately confirmed by the user on beta.3.

<h1>سرویس‌های پیشرفته در نسخهٔ ۲٫۱٫۰</h1>
<p>مالک، انتشار نهایی <strong>ویندوز ۶۴ بیتی</strong> با محدودیت‌های صریح را تأیید کرد؛ پورت بومی لینوکس/macOS و محصورسازی کامل VPN/پراکسی تورنت به مرحلهٔ بعد موکول شدند. انتشار استور کروم به حساب توسعه‌دهندهٔ مالک وابسته است، نه ساخت ZIP ارسال. پرداخت، ساخت حساب یا ارسال به استور انجام نشده است.</p>
<h2>سرویس‌های Debrid</h2>
<p>تنظیمات ← سرویس‌ها، انتخاب Real-Debrid، AllDebrid، Premiumize یا TorBox را دارد. توکن‌ها در مخزن مستقل DPAPI حساب ویندوز هستند و مخزن قبلی Real-Debrid سازگار باقی می‌ماند. ذخیره/آزمایش/حذف برای حساب انتخابی است. فقط برچسب محدود حساب، وضعیت تنظیم و شناسهٔ درخواست منتظر به رابط می‌رسند. توکن در تنظیمات عادی، نتیجهٔ صندوق یا وضعیت موبایل قرار نمی‌گیرد. حساب و میزبان باید اجازهٔ درخواست بدهند؛ تولید لینک ممکن است سهمیه مصرف کند.</p>
<p>Real-Debrid لینک HTTP را تولید می‌کند؛ AllDebrid لینک مستقیم و تأخیردار دارد؛ Premiumize تمام فایل‌های دانلود مستقیم برگشتی را وارد می‌کند؛ TorBox وظیفهٔ دانلود وب می‌سازد و پیش از درخواست لینک فایل تکمیل‌شده آن را بررسی می‌کند. شناسهٔ منتظر پس از بازکردن دوباره می‌ماند. بررسی دوباره، مبدأ تازه ارسال نمی‌کند. نتیجه تا پذیرش صندوق پیگیری می‌شود؛ صندوق پر را می‌توان خالی و دوباره بررسی کرد. حذف پیگیری محلی، کار ابری را حذف یا لغو نمی‌کند. انتخاب کیفیت استریم و مدیریت تورنت ابری وجود ندارند. تولید لینک به‌ترتیب انجام می‌شود و شکستِ مصرف‌کنندهٔ سهمیه، کورکورانه تکرار نمی‌شود.</p>
<p>قرارداد رسمی در ۲۰۲۶/۱۱/۱۷ بررسی شد: <a href="https://docs.alldebrid.com/">AllDebrid</a>، <a href="https://www.premiumize.me/api?hl=en">Premiumize</a>، <a href="https://api.torbox.app/openapi.json">OpenAPI تورباکس</a>. تورباکس در API درخواست لینک، توکن را در query می‌خواهد؛ این نشانی داخلی است و به‌عنوان لینک صندوق ذخیره نمی‌شود. لینک برگشتی حاوی توکن رد می‌شود. آزمون قرارداد محلی، موفقیت حساب پولی زنده را اثبات نکرده است.</p>
<h2>ابزارهای رسانه و مسیر شبکه</h2>
<p>تنظیمات ← ابزارها، نصب/به‌روزرسانی هر ابزار را دارد. دانلود به هش SHA-256 در API انتشار و تعداد دقیق بایت اعلام‌شده وابسته است؛ استخراج فقط نام اجرایی ثابت را می‌پذیرد، تکرار را رد و حجم بازشده را محدود می‌کند. نبود هش، عدم تطابق یا فایل اجرایی نامعتبر نصب را متوقف می‌کند. فایل مدیریت‌شده فقط پس از بررسی جایگزین و مبدأ/تگ/هش در کنارش ثبت می‌شود. مسیر سفارشی همچنان اولویت دارد. دانلود ابزار اختیاری، جداگانه و بسیار بزرگ‌تر از نصب‌کنندهٔ برنامه است.</p>
<p>yt-dlp از <a href="https://github.com/yt-dlp/yt-dlp/releases">انتشار رسمی</a> دریافت می‌شود. توسعهٔ فعال gallery-dl به Codeberg رفته است: <a href="https://github.com/mikf/gallery-dl#installation">README سازنده</a>، <a href="https://github.com/gdl-org/builds/releases">ساخت شبانهٔ gdl-org</a> را معرفی می‌کند؛ باران از همان فایل ویندوز شبانهٔ رسمی استفاده می‌کند، نه فایل پایدارِ فرضی گیت‌هاب. <a href="https://ffmpeg.org/download.html">صفحهٔ دانلود FFmpeg</a> به BtbN لینک می‌دهد که اکنون به <a href="https://github.com/FFmpeg-Builds/FFmpeg-Builds/releases">FFmpeg-Builds/FFmpeg-Builds</a> می‌رسد. Deno از <a href="https://github.com/denoland/deno/releases">denoland/deno</a> است. هنگام تغییر توزیع سازنده باید انتقال مبدأ دوباره بررسی شود.</p>
<p>اتصال HTTP روی IPv4 اینترفیس انتخابی، DNS و سوکت خروجی را از همان اینترفیس و بدون مسیر پیش‌فرض جایگزین عبور می‌دهد. درخواست HTTP رسانهٔ پشتیبانی‌شده از پراکسی محلی با احراز هویت و همان سوکت/DNS می‌گذرد. yt-dlp ملزم به دریافت‌کنندهٔ داخلی و FFmpeg برای پردازش محلی است. قطع اینترفیس سوکت متصل را می‌بندد و درخت فرایند رسانه را لغو می‌کند. این قابلیت مسیر انتقال است، نه محصورسازی سیستم‌عاملیِ ابزار اجرایی دلخواه کاربر یا Kill-switch کل سیستم. همتا/DHT تورنت در موتور aria2 همراه محصور نیست و بنابراین با اتصال اجباری مسدود است. پراکسی عادی وب هم همتای تورنت را پوشش نمی‌دهد. محصورسازی کامل IPv6 و تورنت کار جداگانه می‌خواهد.</p>
<h2>توزیع و شواهد</h2>
<p>نصاب از بازنویسی برنامهٔ بومی در حال اجرا جلوگیری و خروج از Tray را درخواست می‌کند؛ دانلود را به‌زور نمی‌بندد. پس از نصب، شناسهٔ ثابت فایرفاکس ثبت و مسیر میزبان کروم/اج با حفظ شناسه‌های معتبر قبلی تازه می‌شود. همان XPI فایرفاکس ۱٫۰٫۲ با امضای موزیلا همراه است؛ تأیید Add و دسترسی همچنان دست مرورگر است. پوشهٔ آمادهٔ Chromium از تنظیمات باز می‌شود. لینک/شناسهٔ واقعی استور فقط پس از ثبت‌نام مالک و تأیید گوگل استفاده می‌شود؛ CRX خودامضا جای نصب عادی کروم ویندوز را نمی‌گیرد.</p>
<p>فایل <span dir="ltr"><code>tests/advanced.integration.mjs</code></span> قرارداد محلی AllDebrid/Premiumize/TorBox، درخواست پایدار، حذف توکن از خروجی، نگاشت چندفایلی، پراکسی رسانه با احراز هویت و آدرس مبدأ متصل واقعی، لغو فرایند با قطع اینترفیس، بررسی هش و استخراج محدود را آزمون می‌کند. یکپارچه‌سازی بومی/متصل، صحت دانلود مستقیم، Real-Debrid، تسک بیدارکردن، اتصال موبایل و ارتباط مرورگر را پوشش می‌دهد. این‌ها ادعای حساب زنده، مرورگر واقعی/شروع با برنامهٔ بسته، ظاهر یا ممیزی کامل امنیت نیستند. انتقال لینک مستقیم فایرفاکس در بتا ۳ جداگانه توسط کاربر تأیید شد.</p>
